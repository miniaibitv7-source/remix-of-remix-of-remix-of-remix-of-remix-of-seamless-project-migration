- Animation timestamps (attack/hit/facing fields in FX_KEYS) use the page clock, which restarts on reload, so they are stripped from every save and on load and future stamps are ignored when drawing; persisting them froze huge attack effects over the screen after a refresh.
- Resize houses without changing catalog order/lease IDs; update the database catalog alongside map geometry so door access and interior-area rent remain aligned.
- PvP skulls are server-decided: attackers register aggressions via RPC before hitting, victims accept only server-confirmed hits and report deaths, frags need a recorded aggression, and others' skull marks come from the server, never broadcasts; shared rules/penalties live in `skulls.js`.
- Combat stances (full attack / balanced / full defense) live in browser-safe `stances.js`; they multiply basic-attack damage dealt and all damage received, are stored as `p.stance` in the character save, and never change equipment or skill stats.
- Never use ctx.filter or shadowBlur in per-frame canvas drawing (hit flashes, corpses, slashes); they cost ~25ms/frame on phones. Pre-tint once into a canvas or use additive 'lighter' redraws instead.
- Mage training (online and offline) credits magic tries via trainTries() so Magic advances at the same pace as Knight/Paladin weapon skills under the same free/premium training multipliers; never reintroduce a 1-try-per-attack magic rate.
- Lawl hunting-area gates are 3 SQM wide with a cleared trail; forest belts between the city and the northern zones use a coordinate hash, never the seeded rnd(), so the rest of the shared map layout stays identical.
- Underground hunting caves (caves.js) never have 1-SQM passages: tunnels are stamped 2–3 tiles wide, chambers grow 1–3× in area, a widening pass removes pinches and pillars need a 5×5 open patch; caves.test.ts enforces this per zone.
- The in-game HUD overlays a full-screen map in both orientations; the parent page exposes `lawlOpenChat`, `lawlChatUnread` and `lawlSwitchCharacter` to the iframe and only shows its own Personagens/Sair/chat buttons when the HUD is not on screen, so overlays never cover game controls.
- The modal shows the blue player hub (Servidores, Loja, Grind, Status, Inventário, Mercado, Opções) with HP/MP/XP bars and money in its header whenever modalKind/title matches HUB_TABS; existing features are reused inside the hub screens (quests, premium/PIX, outfits, mounts, spells, auto-heal, ranking, online), and buttons for features the game does not have yet carry data-soon and intentionally do nothing until the user asks for them. The inventory is select-then-act because hover tooltips do not exist on phones.
- Character sprites in outfits.js are pixel-art chibis baked once per look/direction/walk step into a cached outlined canvas and drawn with drawImage; keep per-frame drawing to a single drawImage (no per-pixel gradients) so many players stay cheap on phones.
- Mount and monster walk cycles are procedural from their single PNG (leg band cut into skewed/offset columns, body hop and tilt); north/south use front/back PNGs (`<id>_s.png`/`<id>_n.png`) with alternating left/right leg lifts; LawlMounts.draw returns the seat position, tilt and, facing south, an over() redraw so the mount front covers the rider.
- Monster movement uses monster-ai.js for catalog-derived level/strength speed, detection and immediate idle interruption in both local and shared simulation; interpolation uses the same step interval while habitat and safe-zone checks remain authoritative. Chasing monsters share mobChaseStep, which paths to the nearest free tile of the 8 around the target and otherwise queues on the second ring or holds still, so local and shared simulation surround and refill without random shuffling.
- PvP attack mode is a local HUD setting gating only attack attempts; skulls stay server-decided. Duels were removed.
- Items use only the owner's category list in `items.js` (gear category from slot/vocation); new consumables live in the sanitized `p.cons` save map, original potions stay in `hpPot`/`mpPot`, and necklace/backpack gear is appended after the original equipment so GM item indices stay stable.
- Wiki shields/spellbooks live in `items.js` (SHIELDS) and are appended after all older equipment; skill bonuses and resistances are read from the catalog by item name (never from saved numbers), monster hit elements come from `hitElement`, and `canEquip` enforces level and vocation for all gear; base stats of worn shields also come from the catalog via `LawlItems.gearStat`, and the Status skills panel, combat, spells and PvP (spell elements included) read the same live bonuses, so equipping or unequipping takes effect immediately.
- NPC dialogue/shops (openNpc/openShop, blue 'npcx' modal): tapping an NPC walks there via requestWalk+pendingTalk and opens the dialogue on arrival; map speech bubbles are transient npcsTop fields, never saved or broadcast.
- Tiered gear (Aprendiz…Lenda, incl. tier shields, necklaces, backpacks) is retired via `LawlItems.isRetired`: it stays in the `equipment` array only so GM item indices keep resolving to the same shields, and is filtered from shops, GM lists, the encyclopedia and trades and purged from saves on load and after trades.
- Turning in place (holding the joystick knob ~0.35s, or Ctrl+arrow) only changes p.dir and never sets move, so facing-based spells/attacks and the existing pos broadcast follow it without a separate saved state.
- Health and mana potions share one exhaust gate (potionGate in public/reinos.html, delay from LawlItems.POTION_DELAY) used by HUD taps, keys, the backpack and auto-heal; failed attempts never start the delay, and runes/food keep their own timing so they don't block potions.
- Wiki runes reuse the older rune ids (rmissile, rfire, rblast, rdeath, rheal1, rpara) so saved counts carry over; consumables not in the wiki get `retired:true`, which hides them from shops/lists (ofCategory) while saved copies stay usable. Rune areas come from `LawlItems.runeCells`; Magic Field ticks live in `SFX.runeFields`.
- Wiki melee weapons (Knight, `MELEE` in `public/items.js`) are appended after the wiki shields and share their name-based catalog lookup (bonuses, base stats, drops, sell price); enchanted copies split the basic hit by `dmg` percentages and PvP sends that mix so each part meets its own resistance, and two-handed weapons free the shield slot on equip and on load.
- Wiki distance weapons (Paladin, `DISTANCE` in `public/items.js`) are appended after the wiki melee weapons and reuse the same catalog lookup; their wiki "+Speed" bonus is read from the catalog by `equipBonus().speed` and added to the shared player step timing (broadcast as moveMs), never saved as a stat.
- Wiki wands (Sorcerer/Druid, `WANDS` in `public/items.js`) and wiki backpacks (`BACKPACKS`) are appended after the wiki distance weapons, in that order, so GM indices stay stable; wand shots charge their catalog mana per shot and roll catalog min–max damage in the wand's element, enchanted wands add +magic only to spells/runes of their element (`elMagic` → `spellStats().mlEl`/`runeMl`), and the bag holds `BAG_BASE` gear pieces without a backpack, otherwise exactly the worn backpack's catalog slots — only new pickups (drops, depot withdrawals, unequips) are blocked when full, so trades and GM gifts never lose items.
- Hunting Assistant rules (premium + purchase gating, expiry/reset, ground-loot timing) live in `assistant.js` (LawlAssist); ground loot is held by authenticated `lawl_loot_drop/list/pick` RPCs so each bag is delivered once, broadcasts are only refresh hints.
- Wiki helmets, armors and legs (`HELMETS`/`ARMORS`/`LEGS` in `public/items.js`) are appended after the wiki backpacks, in that order, so GM indices stay stable; they reuse the name-based catalog lookup for armor, resistances, skill/speed bonuses, vocation, smith price and drops, and pieces sourced only from wiki Magic Chests (not in the game) drop at half their level band rate.
- Wiki regular items and creature products (`LOOT_ITEMS` in `public/items.js`) are ordinary loot in `p.loot` priced via `lootPrices` (0 = unsellable), rolled per kill by `rollLootDrops` from mapped game monsters; Magic Chests open in the inventory with the same-tier Magic Key (`chestRoll`), giving gold or a listed piece only if it exists in the gear catalog so future rings/amulets join automatically. Wiki ammo reuses id `arrow`, retires older ammo, enforces arrows→bow and bolts→crossbow via `ammoFits`, and GM ammo gifts reuse the server-validated `rune` kind.
- Wiki ammo `el`/`drops` live on the ammo entries in `items.js`; `LawlItems.ammoMix` moves only the ammo bonus share of a basic hit to that element, and dropped ammo rides the ground-loot `loot` map under its item name, so loot RPCs need no schema change.
- Monster elemental resistances live in `spells.js` RESIST (wiki values mapped to game monsters); every player hit on a monster, basic attacks included, goes through `LawlSpells.resist`/`resistMix` keyed by `mobBase`, so bosses share their base monster resistances.
- Wiki monster support abilities (heal, haste, invisibility) only touch transient monster fields through `LawlMonsters.support`; invisible monsters are skipped by drawing, minimap and targeting via `LawlMonsters.hidden`, and the host sends remaining invisibility ms as the last field of shared mob rows so every player sees the same state.
- Wiki necklaces and rings live in `AMULETS`/`RINGS` in `public/items.js`, appended after the wiki boots (new rings only at the end of `RINGS`) so GM indices stay stable; ring skill/speed bonuses use the same catalog lookup as other gear; they drop only from the wiki monsters listing them by name (`from`), `noKit` keeps a piece out of the starter kit, older loot copies become gear on load via `lootToGear`, and the Prison Key opens the Prison Chest by itself through `prisonRoll`.
- Player-dropped gear ("Dropar") is a public ground-loot bag placed on a free adjacent tile (never the south tile unless nothing else is free) via dropSpot(); the player sprite hides its own tile and the "Pegar loot" button sits over the tile below.
- The guild window (opened from Status → Guilda) only reads and changes guilds through `lawlRpc("lawl_guild_action")`; the page routes it through the save chain so gem spending never races a save. Cost, limits and rank permissions live only in the database function.
